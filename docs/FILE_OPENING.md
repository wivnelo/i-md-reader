# 单文件打开与默认应用设计

**状态：已交付，本期用户验收通过（2026-10-26整体确认）。** 文件选择、系统 URL 接收、Markdown Viewer、独立书签和最近文件已实现；不自动替用户设定默认 App。

## 推荐交互

| 入口 | 行为 |
| --- | --- |
| 系统“文件”→ 长按MD → 打开方式 → iMDReader | 启动或唤醒App，直接阅读这份原文件 |
| App右上“＋”→ 打开Markdown文件 | 系统文件选择器，仅选择`.md`或`.markdown`；选定后直接阅读 |
| 系统“文件”→ 显示简介 → 始终以此方式打开 | 使用者选择iMDReader，再由系统确认应用于该文件还是整个文件类型 |

保留现有“本地文件夹”和“公开GitHub链接”。单文件不伪装成已授权文件夹：建议置于单独的“最近文件”分区，显示文件名和文档图标，可移除记录；顶层来源目录排序规则不变。重复打开同一文件复用记录和阅读进度。若文件位于已授权目录内，优先复用该来源并定位树中的文章，避免重复记录。

不提供会误导用户的App内“已设为默认”开关。可以提供简短操作指引；默认应用由系统和用户决定，App不替用户修改现有默认值。

## 接入方式

1. 声明Markdown文档类型，注册`.md`/`.markdown`及对应UTI，使用Viewer角色。支持已有Markdown类型时使用导入声明，不声称拥有该格式，不注册为所有纯文本的默认处理者。
2. 启用原地打开，冷启动和已运行场景统一经`onOpenURL`进入同一个文件打开服务；App内文件选择器也调用它。
3. 单文件独立保存安全范围书签。新建文件访问上下文，区分“文件授权”和“目录授权”，不能直接把文件URL当目录根套进当前FolderAccess流程。
4. 按需持有安全范围访问，通过文件协调读取，复用现有大小/编码/安全渲染保护；只读原文件，不复制为新笔记，不写回、不删除。

## 单文件的权限边界

授权一个MD文件不代表授权父目录或同级资源。独立文件中的相对图片、同级Markdown链接先显示说明，并提供“添加所在文件夹”入口，让用户通过目录选择器明确授权后启用；不自动读取父目录。已在授权来源内的文件继续使用现有相对资源逻辑。

iCloud未下载、断网、文件服务暂时不可用时显示等待/失败和重试，不误判为授权撤销，不自动删除文件或记录。文件改名/移动优先通过书签恢复；无法恢复则保留清晰错误与用户可移除入口。外部打开期间的新请求应覆盖旧请求，不能把较慢的旧文件重新显示到前台。

## 默认打开的验证边界

Apple当前iPad用户指南确认“打开方式”及“始终以此方式打开”，并说明可按单文件或文件类型设置。iMDReader注册类型并安装后，本期用户已确认默认打开与类型冲突处理OK；其他系统/提供方仍需专项检查；工程下限iPadOS 17不等于所有旧系统都具备相同默认应用界面。

## 系统文件类型冲突（2026-10-25）

用户实机截图显示 `.md` 被系统标识为 `com.tencent.weread.common-data`，且“始终打开”后未达到预期。该提示由系统文件类型注册表生成，App无法直接改写其文字，也不能强制覆盖用户的默认关联。

本轮将标准 Markdown 的处理排名从 Alternate 调整为 Default；文件选择器包含系统为 md/markdown 注册的全部类型，避免仅过滤标准 UTI 时遗漏其他 App 注册的 Markdown。读取入口仍检查实际扩展名，不注册微信读书的通用类型，不扩展到其他格式。此调整不能保证消除第三方导出类型的系统冲突；用户随后已确认默认打开与类型冲突OK，本期整体验收通过；未逐一列出的其他系统/第三方组合不扩大验收结论。

## macOS 首阶段适配

Mac 目标使用独立沙箱，文件选择权限为 user-selected.read-only；创建书签使用 withSecurityScope + securityScopeAllowOnlyReadAccess，恢复使用 withSecurityScope，授权生命周期仍由 ScopedAccess 配对管理。iOS 保持原 minimalBookmark 与恢复选项。Mac 本地文件夹及相对文档已做隔离文件冒烟，重启/权限撤销/提供方与系统单文件打开仍待平台验收，详见 STATUS.md。


Mac补充验证：单文件只读范围、记录/进度恢复及外部打开请求优先的3项状态测试通过，公开GitHub真实API读取1项通过。状态测试重建ReaderStore，未覆盖沙箱App进程退出后书签恢复或LaunchServices冷/热打开；后两者保持待测。预览未重启用户当前窗口，隔离QA两源文件哈希未变。
