# 技术架构

## 设计原则

- **原生优先**：Swift + SwiftUI，利用 iPadOS 系统文件选择器、导航与安全存储。
- **无自建服务**：本地文档直接读取，远程文档通过 GitHub API 获取。
- **只读边界**：只实现读操作，UI 与数据层都不提供写回源文件或 GitHub 的入口。
- **轻量可测**：避免 Electron、Flutter、React Native、Node.js 运行时和非必要依赖。
- **阅读质量第一**：能控制精细排版，但须实测内存、滚动、长文稳定性。

## 推荐技术栈（待原型验证）

| 部分 | 技术 | 说明 |
| --- | --- | --- |
| 平台与语言 | iPadOS / Swift 6 | Xcode 构建的原生 App |
| 外壳与树形导航 | SwiftUI | NavigationSplitView + 自定义可折叠树节点；按需加载 |
| 本地来源 | FileManager / UIDocumentPicker | 安全范围 URL 与持久书签，按需协调读取 |
| GitHub 来源 | URLSession + GitHub REST API | 获取仓库目录、文件和条件请求 |
| Markdown 解析 | GitHub Flavored Markdown / cmark-gfm | 输出受控 HTML；解析器封装为可替换接口 |
| 阅读视图 | 系统 WKWebView / WebKit | 加载本地 HTML、CSS，控制排版 |
| 阅读样式 | 自带 CSS + 少量必要 JS | 不加载在线 CSS/JS/CDN |
| 安全存储 | Keychain | 仅存 GitHub 只读凭据 |
| 偏好与索引 | UserDefaults + 本地文件缓存 | 首版不引入数据库，规模扩大再评估 |

**注意**：`swift-markdown` 提供基于 cmark-gfm 的 Markdown AST 能力，但它不是可直接替代阅读排版引擎的完整 UI。应在原型中比较「GFM → 安全 HTML → WebKit」与可用的纯原生渲染实现；当前倾向前者，不宣称已通过基准测试。

## 模块边界

```text
App / SwiftUI
├── SourcesSidebar        # 来源列表、树形目录、选择状态
├── ReaderScreen          # 阅读视图、标题导航、阅读偏好
├── SourceRegistry        # 来源与安全书签元数据
├── LocalFolderProvider   # 列目录、读取文件、授权恢复
├── GitHubProvider        # URL 解析、只读认证、API、刷新
├── DocumentResolver      # 相对文件/图片/链接统一解析
├── MarkdownRenderer      # Markdown → 安全 HTML → CSS
└── ReaderStateStore      # 展开状态、阅读位置、缓存
```

本地与 GitHub 统一成 `DocumentSource` 抽象，树形节点至少包含：稳定 ID、来源 ID、相对路径、节点类型、显示名称、可选版本标识。UI 不直接耦合特定存储提供者。

## 本地文件夹访问

1. 用户通过系统文件选择器授予文件夹权限。
2. 保存系统允许的持久访问标识；再次打开时恢复访问。
3. 读取前开启 security-scoped resource 访问，完成后释放。
4. 对来自 iCloud Drive 等文件提供方的内容考虑文件协调、尚未下载、移动或撤销授权的情况。
5. 仅以用户授权的文件夹为访问边界；不对未授权路径进行扫描。

参考：[Apple — Providing access to directories](https://developer.apple.com/documentation/uikit/providing-access-to-directories)。

## GitHub 读取与私有仓库授权

- 公开仓库可无登录访问，但要处理 API 限流、分页与缓存。
- **个人测试阶段**可使用只限定目标仓库、具有 `Contents: read` 权限的 fine-grained token，保存在 Keychain；不硬编码、不提交、不发送给第三方。
- **未来公开分发**优先评估 GitHub App + 用户授权（PKCE）；认证方式需要在发布前进行安全评审，不能把 App secret 放进 iPad 包。
- 只调用读取端点；解析 GitHub 网页 URL 时须分离 owner/repo/ref/path，处理分支名歧义。
- 网络请求采用取消、超时、重试退避、ETag/条件请求和明确的错误分类。
- 缓存以仓库标识、ref/commit SHA、文件路径、内容版本为键；权限撤销后不应继续展示私有缓存（具体擦除策略在实现时确认）。

参考：
- [GitHub — Repository contents API](https://docs.github.com/en/rest/repos/contents)
- [GitHub — GitHub Apps 与 OAuth App 的区别](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps)
- [Apple — Keychain](https://developer.apple.com/documentation/security/keychain-services)

## 阅读渲染与安全

- 解析 Markdown 后对输出 HTML 进行安全处理；不能把仓库中的任意 HTML、脚本当作可信代码执行。
- 使用严格内容策略，默认禁止远程脚本、任意导航和不受控资源请求。
- 自带样式与所需字体/高亮资源，避免外部 CDN。
- 图片加载经统一资源解析器控制：本地相对路径不越过授权根目录；远程图片按来源限制或显式策略处理。
- 内部 Markdown 链接转换成应用内部的文件导航，不通过浏览器误打开新页面。
- 复用阅读视图、异步解析、延迟展开目录；对长文档测试内存、滚动和滚动位置恢复。

## 关键待验证风险

1. WebKit 的长文章滚动、选择复制、深色切换与动态字体性能。
2. 表格、代码块、中文标点及 iPad 横竖屏下的排版细节。
3. security-scoped 目录在重启、iCloud Drive 和外部文件提供方中的持久行为。
4. 私有 GitHub 授权和缓存的安全边界。
5. GitHub 巨型仓库目录树与 API 限额下的访问策略。

以上均是设计与研究结论，**不是已经实现或验收的功能**。
